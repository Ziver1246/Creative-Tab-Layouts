# Creative Tab Layouts concepts

This document explains the main concepts of **Creative Tab Layouts** (CTL).

> Copy-ready code: [EXAMPLES.md](./EXAMPLES.md)  
> Method reference: [API.md](./API.md)

## What CTL is

**Creative Tab Layouts** is an API and layout system for organizing creative tabs using pages, sections, headers, banners, and fallback pages.

CTL does not replace Minecraft's original creative tab registry. The tab still exists. CTL controls how its content is displayed inside the creative inventory.

```text
Minecraft keeps the creative tab.
CTL rebuilds the visible content of a controlled tab.
```

## Controlled tab

A **controlled tab** is a creative tab whose visible content is managed by CTL.

A tab becomes controlled when a plugin calls:

```java
ctx.controlTab(tabId)
```

It can also receive contributions if another plugin uses:

```java
ctx.contributeTab(tabId)
```

`contributeTab` only returns a tab if it was already controlled. It does not force a tab to become controlled.

## Subtab

A subtab is an existing creative tab grouped under another creative tab. The parent remains the visible top-level tab and CTL shows its direct children through a side panel.

A subtab may keep its original Minecraft layout or be controlled by CTL. The parent does not need to be controlled. Subtab groups are not nested.

## Layout

A **layout** is the complete structure of a controlled tab.

It can contain:

```text
overview page
base pages
addon pages
fallback pages
sections
entries
headers
banners
```

General visible order:

```text
Overview Page → Base Pages → Addon Pages → Fallback Pages
```

## Page

A **page** is a page inside a creative tab.

It is used to split large tabs without creating new Minecraft tabs.

Conceptual example:

```text
Building Blocks
├─ Wood
├─ Stone
├─ Deepslate & Tuff
├─ Nether & End
├─ Resource Blocks
└─ Copper
```

## Overview page

An **overview page** is an initial visual page.

It is declared with:

```java
tab.overview(pageId);
```

Characteristics:

```text
- One can exist per tab.
- It appears before base pages, addon pages, and fallback pages.
- It does not receive CtlPageBuilder.
- It does not contain normal entries.
- It uses a banner associated with pageId.
```

Banner path:

```text
assets/<namespace>/ctl/banners/<path>.json
```

## Base page

A **base page** is a main page of the layout.

It is declared with:

```java
tab.page(pageId, page -> {
});
```

Base pages appear after the overview and before addon pages.

## Addon page

An **addon page** is an additional page intended for addons, compat integrations, or external content.

It is declared with:

```java
tab.addonPage(pageId, page -> {
});
```

Addon pages appear after base pages and before fallback pages.

## Fallback page

A **fallback page** is an automatic compatibility page.

It preserves external items added to a vanilla tab by mods that do not use CTL.

Available modes:

```text
BY_MOD_SECTION → one final "Mods" page, one section per mod.
BY_MOD_PAGE    → one final page per mod.
```

Fallback pages always appear at the end.

Fallback is not a manual layout API. If a mod wants full control, it must use `addonPage`, `contributePage`, or `contributeSection`.

## Section

A **section** is a group inside a page.

It is declared with:

```java
page.section(sectionId, section -> {
    section.add(Items.DIAMOND);
});
```

A section can have a header visual associated with `sectionId`.

Header path:

```text
assets/<namespace>/ctl/headers/<path>.json
```

## Base section

A **base section** is a normal section created with:

```java
page.section(sectionId, builder);
```

Inside a page, base sections are ordered before addon sections.

## Addon section

An **addon section** is an additional section created with:

```java
page.addonSection(sectionId, builder);
```

It appears after base sections.

## Contributing vs creating

CTL distinguishes between creating new content and contributing to existing content.

Create:

```java
.page(...)
.section(...)
```

Contribute:

```java
.contributePage(...)
.contributeSection(...)
```

Practical rule:

```text
page(...) / section(...) create.
contributePage(...) / contributeSection(...) modify something that already exists.
```

If you try to create two pages with the same id, CTL treats it as an error. If you want to add content to an existing page, use `contributePage`.

If you try to create two sections with the same id inside the same page, CTL treats it as an error. If you want to add entries to an existing section, use `contributeSection`.

## Entry

An **entry** is a visible or reserved content unit.

Public types:

```text
add(...)     → simple item.
stack(...)   → ItemStack generated by Supplier.
dynamic(...) → dynamic ItemStack list using registries.
empty(...)   → reserved empty slot.
```

Entries can be directly in a page or inside a section.

## Direct entries vs section entries

A page can have direct entries:

```java
page.add(Items.DIAMOND, Items.EMERALD);
```

It can also have sections:

```java
page.section(id("gems"), section -> {
    section.add(Items.DIAMOND, Items.EMERALD);
});
```

Direct entries are rendered before the sections.

Visual order inside a normal page:

```text
Direct entries
padding until row completion
Section header
Section entries
padding until row completion
Next section header
...
```

## Collapsible section

Section headers can be collapsed from the creative inventory. Collapsing hides the section entries while keeping its header visible. This is navigation state for the current session, not layout data registered by a plugin.

## Header

A **header** is the visual associated with a section.

Rendered size:

```text
162 x 18 px
```

If no visual JSON exists, CTL uses the simple header frame.

## Banner

A **banner** is the visual associated with an overview page.

Rendered size:

```text
162 x 90 px
```

If no visual JSON exists, CTL uses the simple banner frame.

## Priority

`priority` controls order inside the same group.

Rule:

```text
lower priority → appears earlier
same priority → insertion order wins
```

This applies to:

```text
base pages inside base pages
addon pages inside addon pages
base sections inside base sections
addon sections inside addon sections
entries inside their placement group
```

`priority` does not mix groups. An addon page does not appear before a base page only because it has lower priority.

## Occurrence

`occurrence` means which appearance of a target item is used for `addBefore` or `addAfter`.

It is 1-based:

```text
1 = first appearance
2 = second appearance
3 = third appearance
```

`0` or negative is invalid.

More details: [API.md#occurrence-in-addbefore-and-addafter](./API.md#occurrence-in-addbefore-and-addafter)

## Visual datagen

CTL includes a datagen API for generating header and banner JSON.

Package:

```text
com.ziver.tab_layouts.api.datagen
```

It is used to generate files such as:

```text
assets/<namespace>/ctl/headers/<path>.json
assets/<namespace>/ctl/banners/<path>.json
```

## Public packages vs internals

Use only:

```text
com.ziver.tab_layouts.api
com.ziver.tab_layouts.api.layout
com.ziver.tab_layouts.api.plugin
com.ziver.tab_layouts.api.datagen
```

Do not use:

```text
com.ziver.tab_layouts.internal
com.ziver.tab_layouts.client
com.ziver.tab_layouts.mixins
```

Those packages are not stable API.
